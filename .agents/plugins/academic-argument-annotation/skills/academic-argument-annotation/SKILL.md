# 论证脉络｜学术论文双栏批注

## 目标

根据用户提供的学术论文和课程信息，生成一个完整、独立、可离线打开的双栏批注 HTML 文件。重点是准确呈现作者如何提出问题、建立主张、组织证据、处理异议并得出结论。输出保存到用户指定文件夹；若未指定，先询问或采用当前项目中用户指定的输出位置。

## 输入与边界

- 接受 PDF、可检索文本、DOI/论文链接或用户粘贴的章节内容。若仅提供链接且需要读取全文，获取可访问的合法全文；不得编造缺失原文。
- 询问或从上下文提取课程名称、课程编号、教师、学生、日期等页眉信息；未知字段省略或标为未提供，不要猜测。
- 保留原文段落顺序、标题层级、引文和关键术语。原文摘录应服务于分析，避免无必要地复现整篇受版权保护论文；用户提供的全文可用于其请求的转换和分析。
- 明确指出 OCR 不确定、公式/表格提取缺失、页码不完整等材料限制。

## 工作流程

### 1. 阅读和建立结构图

先检查论文全文是否可读，识别摘要、引言、相关研究、理论框架、方法、结果、讨论、局限和结论等实际章节。不要假设所有论文采用相同结构。

长论文必须分章节处理：每章先产出结构化章节摘要，再综合为全篇论证图。章节摘要至少记录：

- 本章要回答的问题或承担的功能；
- 关键主张及其与全文 thesis 的关系；
- 使用的证据、数据或推理；
- 对异议、替代解释或局限的回应；
- 与前后章节的衔接；
- 需要回看原文核实的点。

完成章节摘要后，跨章节核对术语、主张和证据的连续性，组装完整论证链，避免把局部摘要简单拼接成互不相干的段落。若上下文容量不足，先保留章节摘要和待核实清单，再继续逐章处理。

### 2. 划分段落并标注论证角色

以论文自然段为基本单位，给每个段落稳定编号（如 `p-intro-01`），并建立左栏原文/译文与右栏批注的一一映射。标题、图表说明和公式可以单独编号并说明其作用。对每段记录：

1. **段落功能**：如提出问题、界定概念、综述争论、提出主张、描述方法、提供证据、解释结果、处理反驳、承认局限、总结。
2. **逻辑角色**：段落如何承接上文、支持何种子主张、为后文铺垫或限制结论。
3. **论证技巧/潜在漏洞**：指出具体修辞策略、推理跳步、证据边界、因果识别问题、代表性限制、概念含混或未处理替代解释。没有明显漏洞时如实说明，不为凑数而臆造。

### 3. 逐段翻译与高亮

- 每段先呈现英文原文，再呈现中文译文，段间保持对应关系。
- 中文以学术语体意译，忠实表达论点、限定条件和因果关系，不逐词硬译。术语在全文保持一致；必要时首次出现附英文术语。
- 英文原文只对具有明确论证作用的短语/句子高亮，不要整段涂色。五类标记如下：
  - 黄色 `thesis`：全文核心主张、章节主张或关键推论；
  - 红色 `concept`：定义、关键概念、理论术语；
  - 蓝色 `evidence`：数据、观察、引用研究或经验发现；
  - 绿色 `counter`：让步、异议、反驳、回应及限定；
  - 紫色 `method`：研究设计、样本、测量、程序、识别策略或分析方法。
- 同一片段只使用最主要的一类。高亮颜色与图例一致，并提供可访问的文本标签或图例说明；颜色不能是唯一的信息载体。
- 译文不加颜色高亮。

### 4. 处理表格和公式

遇到表格密集、公式密集或 PDF 提取易错的论文时，先把相关内容整理为 Markdown 表格/结构化公式说明并核对原文，再转入 HTML。不要依赖脆弱的嵌套排版来重现复杂表格。关键公式应保留符号、定义、编号和语境解释；若无法可靠还原，标出需人工核验处，不要猜测。HTML 使用语义化表格和可横向滚动容器；公式优先使用原文可复制的文本/MathML，除非用户明确允许外部依赖，否则不依赖在线公式服务。

### 5. 生成并核对 HTML

输出单个 `.html` 文件，包含完整 CSS 和必要的小型脚本。默认不加载外部字体或脚本，保证离线可读；提供字体回退：Lora/Georgia/serif 用于英文正文，IBM Plex Sans/系统无衬线用于界面，中文使用常见系统中文字体。若可联网但用户允许外部字体，可用字体 CDN，同时保留离线回退。

生成后检查 HTML 结构、段落编号是否一一对应、章节锚点是否有效、颜色图例、移动布局、译文和批注是否缺段，以及引文/数字/公式是否遭到意外改写。不要声称已浏览器视觉检查，除非实际完成。

## HTML 页面规格

### 顶部区域

- 深海军蓝固定/醒目导航区：论文标题 + 用户给出的课程信息；过长标题应合理换行。
- 五类颜色图例，文字标签分别为：核心论点 / 关键概念 / 实证证据 / 让步与反驳 / 方法论。
- 可选提供阅读进度或段落计数，但不能挤压标题与图例。

### 章节导航

- 页面上方提供 sticky 章节导航，可跳转到论文各主要章节及底部总览。
- 锚点必须唯一；考虑导航栏遮挡锚点，使用 `scroll-margin-top`。
- 小屏幕上导航可换行或横向滚动，不得覆盖正文。

### 主体双栏

- 桌面端左右双栏：左栏英中对照，右栏逐段批注；两边段落编号一致，便于追踪。
- 左栏每个段落顺序为：英文原文（Lora 衬线风格、带五类高亮）→ 1px 细分隔线 → 中文译文。中文块放在左栏内，使用 `#f0ece2` 浅米色背景及左侧细竖线，不添加论证颜色高亮。
- 右栏每段对应一张中文批注卡，包含“段落功能”“逻辑角色”“论证技巧 / 潜在漏洞”。卡片用左色边和浅背景区分；色边作为轻量视觉索引，不替代文字信息。
- 章节标题、段落卡片、表格、脚注需有清晰层级。长文本保持适宜行宽和行距。
- 移动端切换为单栏：每段按英原文、中文译文、批注顺序呈现；不用强制并排缩小。

### 底部论证结构总览

1. 全文逻辑骨架，以“问题 → 核心论点 → 子主张/证据 → 让步或反驳 → 结论”组织；按论文真实论证调整，不存在的环节明确标注。
2. 作者核心主张的一句话版本。
3. 论证最强处一条，并说明依据。
4. 论证最弱处一条，并说明限制或尚待验证之处。

## 推荐文档结构

```text
<header>论文标题、课程信息、颜色图例</header>
<nav aria-label="章节导航">章节锚点</nav>
<main>
  <section id="...">
    <h2>章节名</h2>
    <div class="paired-paragraph" id="p-...">
      <article class="bilingual">英文原文 / 中文译文</article>
      <aside class="annotation">功能 / 逻辑角色 / 技巧与漏洞</aside>
    </div>
  </section>
  <section id="argument-overview">论证结构总览</section>
</main>
```

## 交付

- 将 HTML 写入用户指定文件夹，文件名使用论文标题的安全短名；若目标文件已存在，避免覆盖，改用新文件名或先征求用户选择。
- 回复包含文件链接、论文处理范围，以及材料提取或复核限制。简要说明章节拆解方式（若适用）。
- 如果论文很长，不得因为生成页面而省略论证步骤；可在 HTML 中完整呈现用户要求的范围，范围外内容须明确说明。
